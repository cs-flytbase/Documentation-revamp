# Voice Corrections

Rules learned from reviewer feedback on tone and language.
Appended to by the memory updater when reviewers correct voice/tone issues.

---

- [voice] YouTube embed must be placed immediately after the H1 title in the release note — not at the end of a section, not after an introduction paragraph. It is always the very first thing after the title.
- [voice] Never use "we" to refer to FlytBase. Use "FlytBase" or passive voice instead.
- [voice] Release notes must start with the problem in concrete, real-world terms before introducing the feature. Never lead with the feature name.
- [voice] Keep real-world examples from the PM doc word-for-word. Do not paraphrase or genericize them.
- [voice] No marketing language — never use "revolutionary", "seamless", "cutting-edge", "best-in-class".
- [voice] State limitations honestly and directly. Do not soften or omit constraints.
- [voice] Release notes speak directly to the operator using "you" and "your". Doc pages use imperative voice ("Click", "Navigate to", "Select") without excessive "you".
